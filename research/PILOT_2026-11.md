# Development pilot, November 2026 — plan frozen before the first review

**Status: exploratory pilot on development fixtures.** This file was written before any
reviewer saw a fixture. Only a toy request outside the corpus was used to check that the
transport works. It is copied into the run's frozen files by `rbs prepare`. Nothing here is a
benchmark result or a confirmatory test.

## Question

Given the same candidate change and the same written contract, do three AI reviewers
miss the same planted defects? Does a panel of three different model families behave
differently from three samples of one model, in faulty approvals and in joint misses?
Secondary: does the author's note change the panel's faulty approvals?

## Design

Configuration: `configs/pilot-local.json`. Transport: `configs/transport.ollama-pilot.json`.

| Arm | Reviewers | Author note |
| --- | --- | --- |
| solo_blind | model A | no |
| panel_blind | model A ×3 (independent samples) | no |
| panel_informed | model A ×3 | yes |
| panel_mixed | models A, B, C | no |

15 pairs × 2 variants (control, faulty) × 10 reviewer jobs = 300 jobs, in an order
shuffled with seed 20261110. Up to three requests run concurrently. Aggregation is
any-block: one request_changes blocks the candidate.

## Models and selection rule

Three locally installed instruction models from three different vendors, at most
36B parameters, with a thinking mode, selected from the local inventory for runtime
before any fixture review: A = gpt-oss:20b (OpenAI, MXFP4), B = qwen3.6:35b (Alibaba,
Q4_K_M), C = gemma4:26b (Google, Q4_K_M). The run freezes the exact Ollama digests and
server version in `transport/transport.json` before the first request.

## Settings

One stateless Ollama /api/chat request per job; text only, no tools, no memory. Output
constrained to the review schema during decoding (allOf removed for the decoder; the
harness validates the full contract afterwards). Thinking: A medium, B and C enabled.
Sampling: each Modelfile's defaults (temperature 1.0), seed derived from the job ID.
Output cap 8192 tokens per job, thinking included; a truncated answer is invalid_output.
Timeout 900 s. No retries. The prompt text is `prompts/reviewer.txt` plus the packet files,
rendered by `rbs.transport.build_prompt` with line numbers on Python files.

## Measures and comparisons

- Faulty approvals per arm, with all-scheduled bounds (primary descriptive measure).
- Joint target misses between reviewer slots in panel_blind and panel_mixed.
- Harness comparisons (family-cluster bootstrap, exploratory): panel_mixed − panel_blind,
  panel_blind − solo_blind, panel_informed − panel_blind.
- Control rejections per arm; target recall after adjudication.
- Resources per arm: input and output tokens, latency. Local compute; USD cost stays null.

## Adjudication

Blocking reviews of faulty variants are judged from grading packets that hide model and
arm, with the rubric in `research/ADJUDICATION.md`. The judge is Claude Opus 5.5 acting
as this repository's engineering agent: an LLM, not a human, which designed this pilot
and knows the targets. Method `external_judge`. Controls are `not_applicable`. Unclear
matches are `unresolved`. A human audit of a random sample is the stated next step.

## Limits accepted in advance

- Panels use three reviewer calls, solo uses one: comparisons are not resource matched.
- Same-model panels are independent samples at temperature 1, not independent reviewers.
- 15 small synthetic families; the agent has read them; no held-out claim is possible.
- Training-data overlap with similar bug patterns is unknown and not inferred.
- Input tokens are Ollama prompt_eval_count, which excludes prompt-cache hits; output
  tokens include thinking. Latency includes contention between concurrent requests.

## Rules fixed now

No job is excluded. Failed, truncated or invalid outputs stay recorded and widen the
bounds. No prompt, model or setting changes after the first fixture request; any change
means a new run. Negative or null results are reported with the same prominence.
